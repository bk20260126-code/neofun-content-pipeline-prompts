# Content Pipeline Prompts

레퍼런스 하나를 발행 가능한 SNS 초안으로 바꾸는 **AI 역할 프롬프트 묶음**입니다.
설치할 것도, 가입할 것도, API 키도 없습니다.

```
아이디어 → 채점 → 브리프 → 초안 → QA → (선택) 이미지 → (선택) 성과 분석
```

---

## 0단계 — 내 AI가 이 폴더를 읽을 수 있는지 확인

이 팩은 두 방식 중 하나로 씁니다. 어느 쪽인지에 따라 시작하는 법이 다릅니다.

**A. 파일을 직접 읽는 도구 (권장) — Claude Code, Cursor, Claude Desktop 프로젝트**

이 도구들은 폴더를 열어두면 그 안의 파일을 직접 읽습니다. 아래 "시작하기"를 그대로
따라 하면 됩니다.

**B. 파일을 못 읽는 도구 — 일반 ChatGPT 웹·앱 채팅**

일반 채팅창은 `skills/onboarding/SKILL.md`라는 **경로**를 줘도 실제 파일을 읽지
못합니다. AI가 파일명만 보고 그럴듯한 내용을 지어낼 수 있는데, 그러면 이 팩이
전혀 작동하지 않은 것과 같습니다. 이 경우:

1. 쓸 파일을 열어서 **내용 전체를 복사**합니다 (`skills/onboarding/SKILL.md`부터)
2. 채팅창에 그 내용을 그대로 붙여넣고, "이 지침대로 나를 인터뷰해줘"라고 이어서 씁니다
3. 다음 단계(`agents/idea-scorer.md` 등)로 넘어갈 때마다 그 파일도 같은 방식으로 붙여넣습니다

번거롭지만 확실합니다. **어느 방식인지 모르겠으면 A를 시도해보고, 인터뷰 질문이
파일 내용과 다르게 나오면(예: 8개가 아니라 다른 질문을 하면) B로 전환하세요.**

## 시작하기

1. 이 폴더를 내 프로젝트에 복사합니다 (A 방식이면 그 폴더를 도구에서 엽니다)
2. AI에게 이 한 줄을 보냅니다

```
skills/onboarding/SKILL.md 대로 나를 인터뷰하고 BRAND.md를 작성해줘
```

**빈 파일을 채우지 않습니다.** AI가 질문 8개를 하나씩 던지고, 모호하게 답하면 다시 묻고,
끝나면 `BRAND.md`를 대신 써줍니다. 20분 걸립니다.

3. 그다음 아이디어를 넣습니다: `agents/idea-scorer.md 규칙으로 이 아이디어를 채점해줘`

### 왜 인터뷰인가

빈 템플릿은 아무도 안 채웁니다. 채우더라도 "우리는 진정성 있게 소통합니다" 같은 말이 들어가고,
그러면 다른 회사 이름으로 바꿔도 말이 되는 글이 나옵니다.

인터뷰는 실제 문장, 실제 고객, 실제로 있었던 일을 캐냅니다. 없는 성과는 만들지 않고
`[VERIFY]`로 남깁니다. 차이는 전부 여기서 옵니다.

## 무엇이 들어 있나

### 핵심 4개 — 외부 서비스 없이 바로 작동합니다

| 파일 | 하는 일 |
|---|---|
| `skills/onboarding/SKILL.md` | **가장 먼저 실행.** 인터뷰해서 `BRAND.md`를 대신 씁니다 |
| `agents/idea-scorer.md` | 아이디어를 12점으로 채점. **8점 미만이면 쓰지 말라고 반려합니다** |
| `skills/strategist/SKILL.md` | 주제·앵글·훅을 정해 브리프로 만듭니다 |
| `skills/writer/SKILL.md` | 브리프 하나로 플랫폼별 초안을 씁니다 |
| `skills/qa-editor/SKILL.md` | 초안을 브랜드 규칙과 대조해 승인/반려합니다 |

여기에 `rules/avoid-slop.md`가 모든 단계에 붙습니다 — AI 티가 나는 표현을 막는 금지어 목록입니다.

### 선택 3개 — 외부 서비스가 있어야 합니다

| 파일 | 필요한 것 |
|---|---|
| `agents/viral-postmortem.md` | 없음 (훅 감사·슬롭 스캔) |
| `skills/carousel/SKILL.md` | 이미지 생성 서비스 (원본은 Higgsfield 기준) |
| `skills/analyst/SKILL.md` | SNS 분석 데이터 소스 (원본은 Postiz 기준). 결과 보고는 Slack이 없어도 `STATE.md`에 남습니다 |

없어도 핵심 4개는 그대로 돌아갑니다.

## 가장 중요한 규칙 하나

**아이디어 채점에서 8점 미만이면 글을 쓰지 않습니다.**

대부분의 콘텐츠 문제는 글솜씨가 아니라 **쓸 가치가 없는 걸 쓰기 시작한 것**에서 옵니다.
`idea-scorer`는 그 지점에서 멈추게 하려고 있습니다. 점수를 올리려고 기준을 흔들지 마세요.

## 아이디어 인박스 (선택)

`strategist`는 인박스에서 그날의 씨앗을 먼저 찾습니다. 인박스는 아무거나 됩니다 —
Slack 채널, 메모 파일, 그냥 붙여넣기. 없으면 스스로 리서치합니다.

인박스에 넣는 형식:

```
[URL 또는 아이디어]
angle: (선택 — 특정 관점)
style: (선택 — listicle / guide / contrarian ...)
```

## 상태 관리 (선택)

여러 단계를 며칠에 걸쳐 돌린다면 `STATE.md` 같은 파일 하나를 만들어 지금 어느 단계인지
적어두세요. 프롬프트들이 그 파일을 읽고 씁니다. 한 번에 다 끝낸다면 필요 없습니다.

원본 파이프라인은 여기에 **회로 차단기**를 뒀습니다 — QA가 2번 연속 반려하면 자동 재시도를
멈추고 사람을 부릅니다. 자동화로 돌릴 계획이면 이 규칙을 꼭 넣으세요. AI가 스스로 통과할
때까지 고쳐 쓰게 두면 기준이 무너집니다.

## 어디서 왔나

2026년에 만들어져 운영된 일 콘텐츠 파이프라인에서 **역할 프롬프트와 검수 규칙만** 추출했습니다.

원본에 있었지만 **뺀 것**:
- 발행 자동화 — 원본에서도 연결된 적이 없는 미완성 계층이었습니다
- 특정 브랜드의 디자인 시스템·포지셔닝 — 그 자리를 `BRAND.md`가 대신합니다
- 특정 Slack 워크스페이스·채널 ID

**검증된 것은 프롬프트의 구조와 검수 규칙입니다.** 발행까지 자동으로 도는 전체 파이프라인은
검증된 적이 없으니 그렇게 광고하지 않습니다.
